# moh — CONTEXT

## Glossary

- **Core** — the headless library (`@moh/core`) that runs the agent loop. No UI, no global state.
- **Extending personas** — the two readers `docs/extending/` is split by, never sharing a chapter: the **extension writer** (builds modules against the `@moh/extension` contract: phase hooks, restrict-only veto, lifecycle) and the **library user** (embeds the core: `sessionFromConfig`, the `events` async iterable, headless permission seams). Light alignment rule: a PR that changes a public door (an `@moh/core` export, a hook, a documented grammar) updates the affected `docs/extending/` chapter in the same PR.
- **Client** — a consumer of the Core in-process: the TUI or the CLI. Never talks to providers directly.
- **AgentSession** — one conversation instance inside the Core. Multi-instance by design; subagents are child sessions.
- **Public-surface criterion (ADR-0004)** — `@moh/core`'s index exports only what a client (TUI/CLI/@moh/extension) or a user-facing config surface touches; everything else is internal, imported directly from its defining module (`session/config.ts` now owns `SessionConfig`/`PermissionsConfig`). Re-opening a closed export is an explicit ADR decision. First re-opening: `sessionFromConfig` + its result/error types (ADR-0005).
- **Session assembly / `sessionFromConfig` (ADR-0005)** — the single core-level builder (`session/from-config.ts`) that owns moh.json reading, the project+user MCP merge, provider resolution, subagent/memory wiring, store creation, and `createSession`. Returns an explicit `{ session, store } | { error }` — no silent fallbacks: the old TUI demo-provider swap on broken config is gone; the demo provider runs only when explicitly configured ("mock", the zero-config default). Provider resolution is one path: pre-built instance > explicit ref (CLI `--provider`) > moh.json `provider`. Clients inject only their consent seams (TUI interactive, CLI headless fail-fast) and client overrides (tools, permission flags, sink).
- **Event log** — the append-only sequence of AgentEvents that *is* the session: source of streaming, persistence, and replay.
- **AgentEvent** — a single entry in the event log (`session_start`, `user_message`, `assistant_delta`, `tool_call`, `tool_result`, `model_call`, `done`, `error`, `cancelled`, plus chrome like `permission_*`/`mcp_*`/`memory_updated`/`model_switched`/`skill_invoked`/`extension_event`/`session_note`). `model_call` (#83) records which model served one provider call, its token usage, and (#240) the effective thinking level sent; `reasoning` (#240) persists a completed call's provider reasoning with its opaque continuation artifacts; `done` carries the turn's usage totals and `models` rollup; `model_switched` (#166) records an in-session switch (same session, effective from the next turn); `skill_invoked` (ADR-0011) records a turn-scoped skill prompt attached to a send.
- **Turn** — one send→stream→tools→reply cycle of the agent loop. Loop protection and errors are scoped per turn, not per session.
- **Tool call / tool result** — a paired tool invocation and its outcome, correlated by `callId`. A `tool_call` may carry the effective `timeoutMs` (#300) — resolved by the tool itself via the `Tool.timeoutMs` resolver (defaults included, e.g. bash's 30s), stamped by the tool runner before validation; absent for tools without a timeout concept. The TUI renders it as a live timer (`⏱ elapsed · limit`) on the volatile block head and the deterministic call→result duration on the settled block. The bash tool keeps a per-session re-run ledger (#304): expensive successful suite-like runs save their full output to a temp file (pointer in the result), and an identical re-run on an unchanged git tree within 10 minutes is short-circuited to that pointer — `# fresh` forces a real run.
- **Steering** — user input injected during an active stream: interrupts and re-sends.
- **Provider** — an implementation that talks to LLMs: built-in (anthropic, openai, google, github-copilot, openrouter, kimi-coding, xai — ADR-0010) or custom, registered via `registerProvider` or an `openai-compat` profile in moh.json. Single-shot: it never loops.
- **Wire** — the message format a backend speaks (`anthropic-messages`, `openai-chat`, `openai-responses`, `google`; ADR-0010): a per-model property of the catalog, distinct from the provider (auth + backend + catalog). kimi-coding and github-copilot speak anthropic-messages against non-Anthropic backends; copilot switches wire per model.
- **Endpoint** — a configured Provider instance with its own credentials (e.g. two Anthropic accounts = two endpoints).
- **Route** — a model reference `endpoint/model-id` with a declared fallback chain. The user declares the chain; moh assumes no model equivalence.
- **Provider reasoning** — reasoning output explicitly returned by a provider during a model call. It is distinct from a model's private chain of thought: moh never synthesizes or promises access to the latter. Completed reasoning and its opaque provider continuation artifacts are persisted in the event log so resume, fork, compaction, and later model calls retain faithful context. The TUI shows it only when the user enables its display.
- **Thinking level** — the user-selected reasoning effort for an Endpoint, expressed in the canonical scale `off`, `low`, `medium`, `high`, `xhigh`, `max`. The selected level persists immediately per Endpoint; a model may expose only a subset, which the client shows as unavailable rather than silently remapping.
- **Thinking capability** — the selectable thinking levels a model actually supports, derived from the moh-owned catalog's per-model level map by default, or from an explicit capability declaration in configuration. Never inferred from `reasoning` alone. Provider-native level names (e.g. `minimal`) are normalized at the catalog projection into the canonical scale.
- **Thinking capability declaration** — the explicit, user-owned configuration (`capabilities.thinking` on an endpoint profile: a thinking format plus the supported canonical levels) that supplies thinking capability where no catalog map exists — `openai-compat` endpoints — or overrides it per model on catalog-backed endpoints. Absent = conservative provider default; moh never invents capabilities. Formats mirror the wires: `openai-effort`, `openrouter-effort`, `anthropic-effort`, `google-thinking-level`.
- **ProviderError** — a normalized error from a provider, one of 10 `kinds`: `auth`, `rate_limited`, `quota_exhausted`, `overloaded`, `network`, `invalid_request`, `context_length`, `content_filtered`, `empty_completion` (a finished call with no content, no tool calls and no usage — fallback-worthy, #853), `aborted` (signal, not an error).
- **Phase hook** — the typed seam (e.g. `beforeModelCall`, `onToolCall`) through which extensions observe and influence the loop. Extensions can only restrict tool calls (ADR-0031: `veto`, which kills the call, or `ask`, which hands it to the human consent prompt — a question, never a grant), never grant. Two observation-only seams (ADR-0032, apiVersion 1.1) let an extension record a structured chrome event (`appendEvent` → `extension_event`, runtime-stamped, capped and redacted) and publish one ephemeral footer status (`setStatus`).
- **Extension source** (#834) — where a client loads extensions from, resolved by the single assembly path (`extension-source.ts`: the user's `~/.moh/extensions/` dotdir, files sorted by name, then the project's `moh.json` declarations in file order — that order is hook precedence). A `moh.json` declaration **proposes**, the user disposes: nothing is discovered from a project directory behind the user's back (the `typesafe`/`mcpTrust` precedent). Trust is per registration, not per runtime: `register(def, { bundled: true })` marks code the host shipped and skips consent, so bundled first-party code and consented files share one runtime.
- **Enable consent** (#834) — the one-time question before a loaded extension runs (the TUI asks through the permission modal, naming extension, version and source path, and stating there is no sandbox; the answer is yes/no, never a rule). Bound to the file's resolved path **plus a SHA-256 of its bytes** (`~/.moh/extensions.json`), so an unchanged file loads silently and an edit asks again. Headless clients cannot ask: an un-enabled extension is skipped with a visible `extension_failed { reason: "consent" }`, one stderr line, and an untouched exit code. No sandbox exists — consent is the whole boundary; a declared npm `dependency` is refused (`deps_unauthorized`) until installation exists.
- **Bundled extension source** (#826, ADR-0039) — the second door into the same runtime: code moh ships, hosted generically. A client passes `bundledExtensions: [source]` to `sessionFromConfig`, where a source is `{ name, isActive(readConfig, configFile), activate(context), inactiveNote?(), wire?(read, wiring) }`: the core asks the *extension* whether it is active (an effect-free predicate over an injected config reader — it reads the shape "should this run?", never a vendor key), registers it as bundled code (no consent: the bytes never came from the user's disk, and a bundled extension is not editable at a path), and offers named capability slots through `wire` (the core owns the signature and the plumbing, the extension owns the key and the meaning). An inactive source may supply its own one-line explanation for the log (`inactiveNote`): the core never invents another extension's precondition. `wire` receives a *lazy* instance reader — registration is fire-and-forget and `ready()` is awaited before the first turn, so a snapshot at wiring time would be empty. The core imports no extension package: the first-party list is the clients' (`packages/tui/src/bundled-extensions.ts`), and a library user that mounts nothing assembles a session with no bundled extension at all. Remaining deviation, recorded in the ADR: the core still reads a boolean from the extension's config (activation is one user gesture — the key in Settings *is* the switch — so it must be readable at assembly time).
- **Permission rule** — a matcher that allows/asks/denies a tool, optionally scoped by argument (shell-word tokens for `bash`, realpath-anchored path globs for edits/writes). One grammar shared by moh.json, TUI, and CLI — real, not promised: the canonical string form `tool:argspec` (`bash:git status`, `write:src/**`, bare `bash`) with `formatRule`/`parseRule` in the core (ADR-0007). The effect (allow/deny) rides on the caller, not the string.
- **Permission tiers** — most-specific-wins merge: built-in per-tool defaults < moh.json overrides < in-session runtime rules.
- **Permission veto** — an extension refusing a tool call via `onToolCall`; it overrides user rules and produces the same denied `tool_result`.
- **Out-of-root write** — a write outside the project root: authorizable per-occurrence only, asked again every time, never persists as a rule.
- **Session notes** — the skill-owned `session.md` at `~/.moh/projects/<slug>/` (same project directory as session files and memory), maintained by the `session-memory` skill during turns. The Core guarantees the **path** (rendered in the prompt environment, helper exported) and nothing else: it never reads, writes, compacts, or remembers the content — no fact is stored in both session notes and Memory. No exit-flush: in-turn atomic edits mean a crash loses at most the last update.
- **Pertinent session** — the session the TUI resume picker suggests at startup: the most recent (file mtime) session **not yet consumed**, i.e. without a `session_resumed` chrome event after its last turn (consumption is re-openable: resuming and then working on it again makes it suggestible again). Suggested via a pre-selected banner row in the picker, only when it exists (no banner otherwise); forks are born consumed and never suggested. Proactive in-session suggestions and CLI variants are rejected (ADR-0021).
- **`session_resumed`** — the chrome event (ADR-0021) appended by the core when a session is opened in resume — TUI and `moh run --resume` alike — at resume-open, before any turn; the sole marker of consumption for a session file. `moh compact` is the deliberate exception on the opening side: it opens a closed file for compaction but appends no `session_resumed` — compacting never consumes (ADR-0022).
- **Session display name** — the user-owned name of a session (#477): a permanent override of the derived first-message title, shown in the TUI Home picker and search (which matches both the display name and the derived title). Set from the Home picker (`r`/right-arrow on a session row) or `moh sessions rename <file|id> <name>`; an empty name resets to the derived title. Never touches slugs or file names; a rename is a chrome event in the log, so resume, fork (name inherited) and compaction carry it for free.
- **`session_renamed`** — the chrome event (#477) appended by the core's exported `renameSession(file, name)` when a session is renamed; the LAST one in the log is the display name, and an explicitly empty name is the reset (the log stays append-only, nothing is deleted). Chrome only — never provider context.
- **`session_pinned` / Home pin** — the chrome event appended by the core's exported `setSessionPinned(file, pinned)` when the user pins/unpins a session from the Home picker (ctrl+p); the LAST one in the log is the pinned state, toggling appends either way (append-only). `SessionSummary.pinned` carries it to clients; the Home list floats pinned sessions to the top (then by mtime) with a 📌 marker. Home presentation only — never affects the pertinent-session suggestion or provider context. Home rename/delete moved from `r`/`d` to `ctrl+r`/`ctrl+d` in the same change (→ stays rename).
- **File mention** — the user-typed `@path` token (#488, vision note 3): `@file` and `@dir`, symbols out of scope. The path stays in the message text; the core attaches a structured snapshot on the `user_message` event at send time — file content capped at ~200KB with a declared truncation marker, binaries base64 with a detected mime, directories a recursive path listing only. `read:` permission rules gate every snapshot (`@` is UX sugar, never a bypass); a denied or missing path appends a visible `mention_warnings` chrome event, never a silent drop and never a turn error. Replay rebuilds the attachment text parts, so resume and fork inherit exactly what the model saw. `expandMentions`/`assembleMentions` are exported from `@moh/core`; the fuzzy `@` popup is TUI-only (mirrors the slash popup, arrows captured only while open, activates after whitespace or as the first symbol).
- **Image mention** — the `@path` mention of a png/jpg/webp/gif (#490, vision note 4): rides the #488 mention seam — bytes as base64 on the `user_message` event (~5MB cap, visible refusal above), promoted to a typed image `MessagePart` only when the serving model declares image input (catalog modalities; for catalog-less openai-compat/custom endpoints an explicit `capabilities.multimodal: true` declares it; `capabilities.multimodal: false` vetoes even a catalog grant; never inferred), else the chip stays in the text with a visible warning. Replay rebuilds the image parts for resume/fork.
- **Inline image preview** — the TUI's place-once pixel rendering of image mentions: kitty graphics (placement ids, 4096-byte chunks) or iTerm2 OSC 1337, detected from the environment only, `images.preview: auto|on|off` (default `auto`), universal fallback chip `[image: name WxH]`. A pasted file path (terminal drag-and-drop) inserts as an `@mention`.
- **Session trash** — where deleted sessions go (#478): `deleteSession(file)` moves only the session's `.jsonl` into `~/.moh/trash/projects/<slug>/` (same structure, ids never collide); forks and project memory are untouched, and deleting the currently open session is refused (process-local open registry via `SessionStore.create/open`/`dispose`). Lazy retention: 30-day default (`sessionTrash.retentionDays` in `~/.moh/config`), pruned at delete/listing time, no background job. `restoreSession(file)` moves the file back (refuses a live id collision, no silent overwrite); `listTrashedSessions()` lists id, title, mtime, days left. All three exported from `@moh/core` (ADR-0004). Surfaces: Home picker delete chip (`d`, `y/N` confirm, refusal line) and `moh sessions delete <file|id> [--yes]` + `moh trash list|restore`.
- **Subagent chips / live panel** (#497, vision note 25): one footer chip per active/recent child on their own compact chip row above the action chips (state glyph `◐` running, `⏸` stalled after ~60s without log growth, `✓`/`✗` settled; ordinal only for duplicate names, overflow `+N`, compact `⊙N`); at the head of the tab cycle when any exist; ←/→ clamp at their edges, Enter toggles the live peek panel, Esc (or typing) returns to the composer. The panel is a full-width volatile peek above the footer at every terminal size (the split right column was tried and removed): header (name, elapsed, state, current tool) plus a ~3Hz tail of the child's event stream read through the core `tailChildLog` seam; consecutive assistant deltas coalesce into one truncate-only preview and the tail has a strict visual row cap. On settle it reduces to one line (`✓ done · Xk tok · result in transcript`), then after ~30s the panel and its chip disappear; the static `subagent` block remains the only permanent transcript artifact (#194/#183).
- **Usage quota modal** (#499, vision note 30): the TUI modal on ctrl+q from chat — one row per provider quota window (5h / weekly / monthly, percent or used/limit + reset) with a progress bar and a source badge (● documented / ○ provider-reported / — local measured), plus the always-present local section (this session's tokens per model from the event log). Backed by the narrow **`getQuota(endpoint)` core seam** (ADR-0004 export): probes the endpoint's usage endpoint reusing the auth stores, returns `{ source: "official" | "undocumented"; windows: [...] }` or `null` on any failure — a broken remote degrades to the local section with a discreet note, never an error. Probe is on-open only (60s cache, `r` forces refresh); no background polling.
- **Liveness scanner (ADR-0042)** — the bottom bar's turn-live indicator: `packages/tui/src/scanner.ts` turns a tick into a seven-cell strip (`▮` light, `▯`/`▫` trail, `·` track; ASCII `# = - .` when icons are off) that walks left→right and back, one cell per tick, no wrap — a full round trip is ~1.1s. Pure geometry: `Chat` owns the ~90ms clock, gated on the active turn and on input not being blocked; the frame leaves as one plain string on the `spinner` prop, and the bar colours each cell by the role its glyph means (`scannerRole`) in `err`/`dim`. It encodes exactly one bit — the turn is live — and never progress. Default in every session (it replaced the braille cycle); the `moh update` progress line and the quota modal keep their own frames.
- **Color capability (`NO_COLOR`, #880)** — color, never glyphs and never emphasis: when the variable is present and non-empty no color code reaches the terminal, while bold/dim/italic stay. One seam (`packages/tui/src/color.ts`): `colorEnabled()` for the escapes written by hand (markdown, quota table, preview box), and the palette projection `paintable()`/`useTheme()` for Ink — a projected palette hands Ink `undefined` per color token, and `Theme` stays the honest palette for the math (contrast, hex parsing, the studio). Two consequences: syntax highlighting is skipped (cli-highlight would otherwise paint unmapped roles with its own 16-color theme, unreachable by any projection) and a list cursor degrades to inverse video (`selectionStyle`) instead of vanishing with its fill. The glyph set is the separate `Icons` toggle.
- **Status chips (bottom bar, #876)** — row 2's left slot carries the **permission-mode lead** for every `SessionMode` (`◌ Normal` dim / `◐ Auto-Accept` warn / `⚠ YOLO — unrestricted tools` err, the text dropped by width class down to the bare glyph) — the slot the yolo banner always used: the mode is a statement about the session, never a property of where you are, so it does not sit beside the **projection chip** (`○ vibe`/`◉ dev`) the tail closes with; row 1's left cluster ends with the **Jev chip** (`JevStatusSummary`: `active` when at least one use case judges the session, `off` when none does and at least one was switched off, `inert` when nothing judges and nothing is off — no chip at all when Jev is not registered or has not answered). Read from the extension's own snapshot on the same cheap 2s poll as the MPM chip, never through the ADR-0032 status seam, whose single writer is the `∅ jev offline` outage text. The fixed tail of row 2 reserves its space first, so the cwd absorbs the pressure and keeps its elision marker.
- **Workflow mode** — the per-user on/off state (persisted in `~/.moh/config`, toggled with `/workflow on|off`) that enables the first-party workflow: bundled skills, workflow commands, and the wayfinder frontier panel. When off, nothing about the agent's base behavior changes.
- **Moh Project Map (MPM) foundation** (#614, spec #613): the single headless Core service per project owning a disposable, rebuildable structural projection at `~/.moh/projects/<slug>/project-map/` — sharded JSON, an atomically-flipped manifest, in-memory inverse indexes, and a small append-only crash journal. Read-only query contract with provenance (`query(seedPath)` → `{ paths, provenance }`), `status` of `ready | updating | unavailable` (the `updating` state added by #617). Metadata only (paths, hashes, symbols, relations — never source content); never MemoryStore, event log, or handoff; corrupt/incompatible data is discarded and rebuilt, never migrated. `MpmService` is exported from `@moh/core` (ADR-0004).
- **MPM orientation plan** (#616, spec #613; extended by #759): the small, advisory, source-cited plan the Core injects for eligible codebase tasks as the prompt's turn-scoped `mpm` section. Eligibility draws on three seed sources, descending confidence and labeled in the render: task-named mapped paths (high), exact task symbols resolved in the symbol index (medium), and recency-weighted identifiers from persisted prior-call provider reasoning (low, suppressed after a successful `mpm_query` — the model already oriented itself). Every entry is extracted and fresh (re-hashed against the mapped record), cited with path, coordinate, relation, and a concise reason; a seed resolving to more than 5 files yields no plan at all (`over-threshold`). Low-tier entries render visually subordinate. Stale, ambiguous, or unsupported scopes get no plan — never a guessed one. Deterministic tokenization only: no fuzzy matching, no LLM in the seed pipeline; the map is never updated from reasoning content. Advisory only: never a tool restriction, never source excerpts. Computed per send and recomputed at each prompt assembly, cleared when the turn settles; `SessionConfig.mpm` opts in, `sessionFromConfig` activates automatically when the projection exists.
- **MPM model-nominated queries** (#663, ADR-0028): when MPM is active the session also carries the read-only `mpm_query` tool — the model nominates one seed (exact mapped path, unique path suffix, or symbol name) and receives the plan's trusted format, every entry re-hashed fresh and locally proven; hallucinated or ambiguous candidates are discarded honestly, never guessed. The full result persists in the event log (the accepted exception to "MPM never in the event log" — it is a tool result the model consumed, not map state). Subagents get the tool via preset allow-lists; the `MpmService` never leaves the parent session. Diagnostics distinguish the `model-seeded` fallback reason.
- **MPM user controls and diagnostics** (#618, spec #613; amended by ADR-0026): the user default lives in `~/.moh/config`'s `mpm` section (`enabled`, `quota`, `exclude` — guardian-tolerant) and is **disabled when absent — MPM is opt-in**; the project's moh.json `mpm` section is an explicit two-way override (`enabled: true` opts the project in, `enabled: false` opts it out, absent = inherit). One resolver (`resolveMpmConfig`): an explicit project `enabled` beats the inherited user default; quotas take the strictest field; exclusions union. Discovery honors the extra patterns (negations can re-include only what gitignore dropped — the sensitive denylist is never rescuable). Diagnostics are a read-only metadata projection (`mpmDiagnostics`: status, per-language coverage, sampled freshness, pending work, budgets, exclusions, evictions, and the orientation's last fallback reason) surfaced as `moh mpm` (text or `--json`) and via the settings-panel "Moh Project Map" row (inherit/on/off, writes moh.json; applies to new sessions); never source content, never prompt text.
- **MPM session continuity** (#620, spec #613): subagents receive a bounded, read-only orientation snapshot for their task (`SubagentOptions.mpm.snapshotFor` — rendered plan text only; the child never gets the `MpmService`, the lifecycle, or any mutation surface). Handoff keeps transporting zero MPM data; the receiving checkout may validate handoff file/test hints locally (`validatedWarmupPaths`) and hand the survivors to its own map as a non-blocking warm-up priority. A project identity migration relocates `project-map/` with the project data, and the relocated map is revalidated against the active root before use (`MpmService.revalidate` — absent files are dropped, never trusted).
- **MPM background lifecycle** (#617; external channel resolved by ADR-0027/#654): the session-owned `MpmLifecycle` keeps the projection fresh with adaptive budgets (files/sweep, wall-clock/slice, zero during busy turns) and honest `ready | updating` status. Change observation is one channel per producer: moh's own edits push a targeted immediate refresh (`noteEdit` via `ToolRunner.onFileMutation`); every other change — external edits, git operations, generated files — is caught by the periodic mtime+hash scan while the session is idle. There is no external-notification seam: the debounced `noteExternalChange` path shipped without a producer and was removed (ADR-0027); a future watcher would be a new producer, not a reopening.
- **Browser toolchain (#935, ADR-0029 amendment)** — the optional, moh-owned dependency set behind the native `browser` tool: `playwright-core` plus a Chromium build. Two builds, never conflated: the **headless shell** (`chromium-headless-shell`, ~200 MB) is what a `headless: true` launch actually runs, the **full Chromium build** (~500 MB) is what `browser.headless: false` needs — so the probe reports them separately and `ready` answers the mode the caller asked about. The package lives in the moh-owned root `<home>/.moh/browser-toolchain` (the canonical path is a symlink into a versions directory, so an install swaps it atomically); the browsers stay in **Playwright's own per-user cache**, whose OS-specific location and `XDG_CACHE_HOME` behavior moh never reimplements. Resolution is deterministic and existence-gated: the project's own `node_modules` first (the nearest one walking up from the project root, hoisted workspace installs included), then the moh root — never `NODE_PATH`, a global npm root, or a runtime lookup that could answer from Bun's global install cache. Installation runs the Bun runtime embedded in the moh binary (`BUN_BE_BUN`), so a fresh user needs no npm and no system Bun; the full build and Playwright's system dependencies (`install-deps`, which may ask for the administrator password) are explicit options, never implicit. One lock file plus a staged atomic swap mean a failed or interrupted install leaves a working toolchain exactly as it was. `probeBrowserToolchain`/`installBrowserToolchain`/`browserToolchainRoot` and their status/install types are exported from `@moh/core` (ADR-0004); clients render and ask, and never probe or resolve on their own. **Activation is per project** (`browser.enabled` in that project's `moh.json`), **the toolchain is user-level** (one install serves every project) — the TUI Settings row **Browser** states both halves (`off (this project) · toolchain ready`) and opens the one guided setup modal the transcript warning, `/browser` and ctrl+b also open (#934); because the tool registers at assembly time, a change re-assembles the open session or waits for the next one.
- **Binary** — the compiled distribution of moh (ADR-0013): a self-contained executable built with `bun build --compile` for macOS arm64/x64 and Linux x64, published via GitHub Releases. The Bun runtime and the first-party skills bundle are embedded as assets in the executable (no Node, no Bun, no npm install required); the skills are copied lazily to `~/.moh/skills/` on first run through the existing hash-manifest mechanism. The binary has no repo-relative filesystem assumptions: everything it reads is embedded, in `~/.moh/`, or in the user's project.
- **First-party skills** — the Matt Pocock workflow skills bundled in the moh package and copied to `~/.moh/skills/` at install/upgrade. User-owned: upgraded only when unmodified (hash check); modified ones are left alone with a diff offered.
- **`/mnt` project root / I/O hint** (#918, ADR-0044) — the one environment fact moh reads about *where* a project lives: a root that resolves under `/mnt/` (any mount — `/mnt/c`, `/mnt/d`, …) is a Windows drive mounted into WSL, where every file operation crosses the 9P boundary into the Windows filesystem and grep/glob over a large tree is dramatically slower. Resolved **once, at session assembly** (`AgentSession.rootOnWindowsMount`, realpath-anchored like the permission spine; the filesystem type is never sniffed), never re-probed per turn or per render. Chrome, never provider context, and never an error: the TUI keeps one persistent, never-blocking hint line above its status rows (self-sufficient copy at every width), headless `moh run` prints one stderr line, always on with no config key to silence it — and the distro-filesystem case renders exactly what it did before.
- **Exit-work seam (ADR-0015)** — the bounded interactive-exit path (`packages/tui/src/exit.ts`): cleanup promises are registered with `trackExitWork`, and the CLI terminates the process after a fixed budget — a deliberate double-`Ctrl+C` exit is never held hostage by lingering event-loop handles (Bun HTTP keep-alive sockets).
- **Project identity** (#591/#592) — the key selecting `~/.moh/projects/<slug>/`: a usable Git `origin` wins and is normalized to lowercase `host/owner/repo` (protocol, credentials, port and trailing `.git` removed; nested repository paths retained), so equivalent SSH/HTTPS clones share data. Without one, `.moh/project.json` holds an opaque UUID and its derived slug; unreadable or uncreatable identity falls back to the legacy path-derived slug. When a UUID project later gains an origin, its existing data directory moves once, atomically, to the remote slug with a durable migration note; an already-existing remote directory wins without merge, and an open UUID session pins its old location until close.
- **Session file** — the persisted session: one append-only JSONL event log per session at `~/.moh/projects/<project-slug>/<id>.jsonl` (id = sortable timestamp + short uuid). Sessions are user data; they never live in the project's `.moh/`. **Single-writer** (#400): an open session probes its file's size at every append boundary; growth from elsewhere (another machine over a sync channel, a second process) emits a `session_file_growth` chrome event — a visible warning in the TUI, CLI, and replay — while the local writer's appends stay intact on the tail. Concurrent use of the same session file on two machines is unsupported (serial use only: close on one machine, then resume on the other); forking the session is the recovery path once a warning fires.

- **Detect-and-fork** — the *suggestion* (never an automatic action, ADR-0020) that follows a `session_file_growth` warning: each client projects its own recovery hint (TUI sticky banner with a fork chip; CLI stderr line naming `moh run --session <f> --fork`; replay block), while the event itself stays unchanged in the core. The fork inherits the full history via the existing store-level fork; the original file stays intact.
- **Fork now** — the TUI banner action after a growth warning: disposes the current session and activates the forked one (same assembly path as `/reload`), with a discrete "forked (scope) → <id>" note. Fork is reachable in the TUI only from this warning state — no general fork command; `/fork [tree|branch]` picks the scope (#768).
- **Scoped fork (ADR-0043)** — `fork(scope: "tree" | "branch")`: `"tree"` (default) is the unchanged byte-identical full copy; `"branch"` writes the active root→head path (`branchProjection`, internal) as a valid degenerate linear tree — parentIds stripped, source-tree `branch_switched` markers dropped, bookmarks ride their target (pointer rewritten to the id), compaction pointers remapped to ids or dropped visibly (never shifted). CLI: `--fork-scope tree|branch` (separate flag: bare boolean `--fork` must keep working).
- **Resume / Fork** — the two ways a session continues: **resume** appends to the same file (default), **fork** starts a new file inheriting the history.
- **Head** — the tip of the active path in the session file: the `to` of the last `branch_switched`, or the last event if none exists. All appends follow the head; resume reopens there; a switch to any node moves the head immediately and a dangling target falls back visibly. (See `docs/spec/session-tree-format.md`, "Head semantics and chrome events".)
- **Memory** — durable facts kept **across** sessions, per project, at `~/.moh/projects/<slug>/memory/` (index + append-only topic files, dated and session-signed). Written automatically post-turn; never merged by the core — only appended atomically and consolidated by the maintenance subagent.
- **Compaction** — rebuilding the past **within** a session: an in-log `compaction` marker (summary + `upToId` pointer, #578) that replay uses instead of replaying everything. The marker covers only the **active root→head path**: markers resolve on-path (last marker on the path wins — a marker on an abandoned branch is invisible until that branch is active again), the pointer is the id of the last covered event (legacy numeric `upTo` markers read as `line:N`), and a dangling pointer restarts context from the path start with a visible warning (`compaction_dangling` chrome). The log stays integral forever; nothing is ever deleted. Distinct from Memory — no fact is stored in both.
- **Compaction producer** — the **CompactionRunner**, the post-turn component (MemoryRunner pattern) that writes compaction markers: auto-triggered when the last `model_call`'s measured `inputTokens` crosses 80% of the active model's context window (absolute-token fallback when the window is unknown), or forced explicitly by the user (`/compact` in the TUI — turn-scoped, always compacts; `moh compact` in the CLI — opens a closed session file, compacts, and closes it **without** consuming it, never appending `session_resumed`). The verbatim **tail** spans at least 10 turns and at most ~25% of the context window; the **summary** covers only the past, carries task state (never durable facts, which stay in Memory), and chains: a later summary builds on the previous one. After a marker the live prompt is rebuilt through the same replay path resume uses; a fresh measurement, not the stale one, may re-trigger — retries are unlimited with backoff when two consecutive attempts stay above threshold. Failure is fail-silent with a sticky TUI warning (ADR-0022); success surfaces as a discreet chrome event. On by default; `SessionConfig.compaction` overrides (ADR-0022).
- **Maintenance subagent** — the background agent that extracts memory updates and compacts context; invisible to the TUI (a successful extraction surfaces only as a discreet `memory_updated` event/indicator), fail-silent, privileged: it is the only writer allowed to consolidate (newest-wins rewrite with a dated note) and is never reachable through the `spawn` tool.
- **Workflow upstream** — the official Matt Pocock skill repository, polled (opt-out) at startup when workflow mode is on, as the live update channel for first-party skills.
- **Provider config layering (#129)** — provider definitions live in both the project `moh.json` and the user `~/.moh/config` (`provider` + `endpoints` sections, guardian-owned, strict-when-present: a broken section fails loudly at session start). One merge seam (`core/src/provider-config.ts`, `loadMergedConfig`): endpoints merge by `name` per-field (project wins field-by-field, absent fields inherit from user); endpoint keys and the default `provider` reference resolve env var > project > user > `mock`. Session assembly, the TUI status label and the add-provider wizard all read through it.
- **Subscription auth** — the per-endpoint auth method (`EndpointProfile.auth.kind = "subscription"`) that uses a provider plan's OAuth tokens (Claude Pro/Max, ChatGPT Plus/Pro, personal Google) instead of an API key. Absent `auth` = api-key, always. Chosen at `moh provider add` (asked first), re-established with `moh provider login`, dropped with `moh provider logout` — logout and successful re-login are the only token deleters.
- **Preferred model / fallback stop** — the per-endpoint model an endpoint serves *with* when the automatic chain reaches it (ADR-0012). It is the profile's `defaultModel` — one field, one meaning — and it lives wherever the endpoint lives: a project endpoint in `moh.json`, a user-level one in `~/.moh/config` (writable since this change; it used to be display-only). An endpoint is a stop only if it can be one: route-capable type (built-in or `openai-compat`), `fallbackEligible !== false`, and a preferred model present — one predicate (`fallbackIneligibleReason`) shared by the chain builder and the UI, so the settings screen explains the same verdict the route applies. Two independent per-provider controls: the preferred model, and `fallbackEligible` (exclude the whole provider while keeping its model). Neither control ever switches the active provider: Settings → *Fallback models* (one row per endpoint, 📌 model / `✗ excluded` marker, every endpoint listed with the reason it cannot be a stop; `enter` picks the model, `x` excludes/re-includes the provider, `c` clears the model) and `moh provider fallback <endpoint> [model] | --clear | --exclude | --include` (headless; `moh provider status` prints both states) apply from the next session.
- **Billing plan** — the way an endpoint pays for a model: a metered API key or a subscription plan (`billingPlan` on the endpoint profile; absent = metered). A catalog row may declare one pricing entry per plan (`cost` metered, `planCost` subscription), each with its own provenance; the endpoint's billing plan selects the matching entry at runtime, through the `planFor` seam every cost-estimate surface threads (ADR-0046). Never inferred from model names; a zero-only plan record is "included in the plan", which reads as tokens-only, never as free.
- **Model catalog** — the versioned per-subscription-provider model lists (`core/src/model-catalogs/*.json`) exposed through `subscriptionModelCatalog`, plus `catalogEntryFor` — the per-model wire/headers/compat a route target attaches (#159 seam). The wizard shows one right after a successful subscription login; free-text entry is the advanced fallback. #181 makes the catalog the single source for both model pickers: the `/model` in-session modal (ephemeral, next-turn switch, every configured endpoint's list) and the Settings panel's hierarchical endpoint → model picker (persistent: rewrites `defaultModel` + the default `provider` ref in moh.json only; user-level endpoints are display-only there). openai-compat endpoints have no catalog: `listOpenAiCompatModels` (`GET <baseUrl>/models`) supplies their list at picker-open time, free-text remaining the fallback. Since ADR-0046 the catalog is **moh-owned, not vendored**: generated by `packages/core/scripts/build-model-catalogs.ts` from declared aggregators (models.dev primary, OpenRouter filling holes; declared, never deduced) plus a hand-maintained `<provider>.overrides.json` sidecar per file — the only authored surface, every row carrying author/date/reason — with per-row provenance in a committed `manifest.json` and a `generation-report.json` audit trail; freshness is release-pinned (`PRICING_SNAPSHOT.version` = the moh release from that manifest, and CI rebuilds-and-compares without committing).
- **Auth store** — the `auth` section of `~/.moh/config` (guardian-owned, ADR-0006, never a merge candidate): tokens keyed by endpoint name plus `auth.overrides` for the drift-prone captured client_ids/issuers. Tokens never appear in moh.json, session logs, or events. Refresh is core-owned and happens before the single stream call, never mid-stream (ADR-0009).
- **Minted key** — the API key OpenAI's mandatory RFC 8693 token exchange returns at login; it rides the ordinary api-key path even though the endpoint is subscription-authed (hybrid posture). Deliberately not used for Anthropic — the minted key bills Console credits, not the Pro/Max plan.
- **MCP server** — an external tool source declared in moh.json (project, consent required on first use) or `~/.moh/config` (user, trusted). Stdio or HTTP transport; started lazily on first use, stopped at session end.
- **User-config guardian (ADR-0006)** — `core/src/user-config.ts`, the single owner of `~/.moh/config`: the one path constant (`userConfigFile(home)`) and the only read/write helpers, with preservation-mandatory writes (read-modify-write of the whole JSON, temp-file + rename, 0600 file / 0700 dir) so unrelated keys and unknown sections always survive. Known sections: the flat TUI chrome keys (schema owned by the TUI), `mcpServers` (schema owned by `core/mcp/types.ts`) and `provider`/`endpoints` (schema owned by `core/config.ts`, strict-when-present, #129).
- **PromptComposer** — the Core component that assembles the system prompt for every model call from typed sections in fixed order (base, environment, tools, skills, memory, session-state). Clients never touch the prompt; extensions can read it via `beforeModelCall` and append to the trailing `extension_notes` section, never rewrite. One first-party exception (ADR-0011): a turn-scoped **skill prompt** — `send(text, { prompt: { name, text } })` renders the named skill in full in the `skills` section for exactly one turn (dropped when the turn settles; recorded as a `skill_invoked` chrome event, never in the user message). The base `/ask-moh` router command is its only caller today.
- **Base prompt** — the shipped identity/behavior section (English, "reply in the user's language"), overridable in full by a `prompts/system.md` file (`~/.moh` < `.moh`, project wins).
- **MCP tool** — a tool exposed by an MCP server, registered as `mcp__<server>__<tool>` under the same Tool contract and permission spine as built-ins, with a stricter default: ask on first invocation.
- **Subagent** — an in-process child AgentSession spawned via the `spawn` tool from a `SubagentSpec` (inline or a preset: built-in `research`/`implement`, overridable in moh.json `agents`). Strict-subset tool inheritance (MCP tools never inherited), depth 1, own JSONL log, own per-turn loop cap, parallel spawns capped (default 3); child failure surfaces as an error result and never fails the parent's turn.

### Internal collaborators (ADR-0003)

- **Jev (TypeSafe)** — the bundled first-party extension (`packages/jev-guard`, #784) that gives moh typed judgments from a second account: no text, only probabilities/choices per question. Activated by a key in the *user* config (`typesafe.apiKey`, entered from the TUI Settings entry `Jev (TypeSafe)`), never by moh.json — presence of the key IS the activation state, no wizard; without it nothing is registered and one informational `session_note` is recorded. Next to it the config carries the six use-case opt-ins (`typesafe.routing`, `injection`, `classification`, `lint`, `rerank`, `skills`): read at session assembly, they set the state a session *starts* in — the only use case without one is the guardrail, where the stored key is the switch. Session-only changes ride the use-case control surface below. The core knows nothing Jev-specific: the extension rides only the generic contract (`ask`, `appendEvent`, `setStatus`, `beforeTurn`), and the only door it enters through is session assembly, which constructs the bundled definition from the config key. Lifecycle: fail-open (moh behaves exactly as designed without it), the client honors one retry and never throws or synthesizes a judgment, every judgment lands as a full `extension_event`, and an outage shows one `∅ jev offline` status (one stderr line headless). The endpoint and model are hardcoded; state sent per judgment is the tool-call context only (command, cwd, compact git status). Use cases: model routing (#787, above), anti-injection (#791), compaction cut guide (#792), prompt classification (#788), and the **quality gate** (#789, opt-in `typesafe.lint`) — at the end of a done turn that changed files, the project's own convention documents (deterministic name-list discovery; a repo with none gets no gate — rules are never invented) plus the task's unified diff (32 KiB cap) are judged on three fixed questions (conventions, error handling, completeness; a probability below 0.40 is a finding), and a finding asks for a synthetic correction turn through the ADR-0037 `requestTurn` seam, re-judges the corrected diff, and hard-stops after two cycles (`jev_lint_stopped` records a cap stop).
- **`extension_control`** (ADR-0038, apiVersion 1.3) — the client→extension command channel: `AgentSession.setExtensionState(extension, payload)` appends one chrome event addressed to a running extension by its own name, the runtime delivers it to that extension's `onEvent` hooks alone (never another's), and the payload is opaque and JSON-serializable. Its sibling `extensionState(extension, key)` reads one value of that extension's own `state` — how a command reports the resolved state back (neither `setStatus` nor `appendEvent` is a return value). Recording the event keeps the intent replayable; an unknown target is logged and silent, never an error; the channel can only make an extension more restrictive, never grant.
- **Jev use-case control surface** (#832, appendix to ADR-0038) — the uniform way to govern all seven Jev use cases (`guardrail`, `routing`, `classification`, `injection`, `lint`, `rerank`, `skills`) while a session runs: one grammar on the `extension_control` channel (`{ cmd: "usecase", usecase, action }`, with the routing-only `{ cmd: "on"|"off"|"auto" }` form kept for a client that predates it), one snapshot reader (`state.jevState` → per use case a `status` of `on|off|paused|inert`, the config's own value, a `sessionOnly` marker and a one-line note) beside routing's richer `routingState`, and one visible `jev_usecase` line per change stating the asymmetry explicitly ("the config still says off"). **Availability and config are two different bits**: a use case whose dependency the session has (the model pool, the skill roster, the project root) is available whatever the config says — the config only picks the session's starting state, so a warm `on` starts judging from the next turn — while a missing dependency makes it `inert` and its commands are refused, visibly, never silently ignored. Warm state is session-scoped: a session command never writes the config (that is the Settings panel's and `moh jev <use-case> on|off`'s job). The two client surfaces are exactly that split: the TUI's `/jev` modal flips a use case for the open session (it renders the extension's own snapshot and sends its own command, and shows the asymmetry on every row — #833), while the Settings entry and `moh jev <use-case> on|off` write the flags the next session starts in. The guardrail has no config opt-in out of that rule (a stored key is the switch, #784), so its warm switches are session-only by construction, and in `yolo` a warm `off` is **refused** with a visible line — ADR-0031 read strictly: a filter that can be disarmed in the mode that needs it most is not a filter.
- **Model routing** (Jev use case, `packages/jev-guard/src/routing.ts` + `routing-judge.ts` over `core/src/model-pool.ts`, #787) — the per-turn router: the core resolves *which models a session can really reach* (`createModelPool`: shipped catalogs, or one lazy live listing per catalog-less endpoint — never an invented model), the extension owns the three canonical tiers (`economico`/`bilanciato`/`potente`: an explicit `typesafe.tiers` label wins, otherwise blended price terciles, an unknown price staying routable as `bilanciato`), and one Jev call per judged turn sees **only** the last user message (2 KiB) plus the tier-to-model mapping. A switch needs confidence ≥ 0.60 and two consecutive turns naming the same tier (in-session streak, reset on switch/override); it names one ref, applied by the session's own `switchModel` through the `beforeTurn` hook, so the `model_switched` chrome and the fallback machinery are unchanged. Inert (no call, no cost) when routing is off or fewer than two tiers exist; a manual `/model` suspends it for the session (one visible notice); every judgment is one `jev_judgment` event. Session control: `/routing on|off|auto` and `/model auto` (never the config; the pause is per session, and reopening starts from the configuration again), riding the ADR-0038 `extension_control` channel — the client commands a running extension by name, the payload is opaque, delivery is targeted and the intent stays replayable.
- **MemoryRunner** (`memory.ts`, #88) — the post-turn memory trigger inside `AgentSession`: counts completed turns, windows the transcript, runs the extractor with one retry, fail-silent but not lossy (a failed run keeps its turns eligible for the next trigger). Emits a single `memory_updated` event on success; `createMaintenanceExtractor` (the default extractor's maintenance subagent) lives beside it in `memory.ts`.
- **EventLog** (`session/event-log.ts`, #89) — the append-only session log inside `AgentSession`: in-memory storage, sink fan-out, the `events` async-iterator projection, and the serial extension dispatch queue (reentrancy guard; `extension_failed` is terminal and never re-dispatched). Resume seeding stores persisted events without re-appending them.
- **PermissionGate** (`session/permission-gate.ts`, #90) — the 3-tier tool gate inside `AgentSession`: extension veto > user rules > defaults (veto applies even in bypass — extensions can only restrict), then mode handling (bypass / auto-accept / headless) and the user ask flow. An extension `ask` (ADR-0031) enters between the rule resolution and the mode branches: an explicit `deny` rule beats it, an `allow` rule does not suppress it, auto-accept still prompts, bypass ignores it, headless denies it, and it never writes a rule. Owns the "always" persistence decisions: runtime rule (+ `permission_rule_added`) and `mcp__*` trust in moh.json.
- **ToolRunner** (`session/tool-runner.ts`, #91) — same-turn tool execution inside `AgentSession`: schema validation, unknown-tool handling, gated execution via PermissionGate, parallel run (`Promise.allSettled`, `tool_call`/`tool_result` events in completion order) with a sequential downgrade when the provider lacks `parallelToolCalls`. Returns result parts for the feedback user message.
- **TurnQueue** (`session/turn-queue.ts`, #92) — the send queue + steering pump inside `AgentSession`: pending sends run front-first when idle; a later send always preempts the running turn (its promise resolves `{status: "cancelled"}`) and the finishing turn re-pumps, so a steered session chains cancelled → steering `user_message` → new turn.
- **AgentLoop** (`session/agent-loop.ts`, #92) — one agent turn inside `AgentSession`: model calls, streaming deltas, `model_call` buffering and turn usage rollup (#83), the max-iterations cap, the abort/cancelled path, and extension dispatch (turn-start `beforeTurn` before the provider is read, `beforeModelCall`, `afterTurn`). Also owns session-cumulative usage; `session/session.ts` is the thin director that wires all collaborators.
- **`sessionFromConfig`** (`session/from-config.ts`, #100 / ADR-0005) — the single session-assembly path: moh.json read, MCP merge, provider resolution, store creation, `createSession` wiring. Explicit `{ session } | { error }` result; no silent demo fallback.
