# The moh model catalog

These JSON files are **generated by moh's own pipeline** (ADR-0046, #959) from
two declared aggregators plus a hand-maintained sidecar per catalog. They are
the post-login model list the wizard shows, the per-model metadata source for
the wire/headers/compat seam (#164), and the pricing table behind `moh usage`
and the TUI quota modal (ADR-0029).

```
models.dev/api.json  (primary)          <provider>.overrides.json  (hand-maintained)
openrouter.ai/api/v1/models (holes)   +                |
                       \                              /
                        \                            /
                     build-model-catalogs.ts  ──────►  <provider>.json
                                                    +  manifest.json
                                                    +  generation-report.json
```

## Generating

```sh
bun packages/core/scripts/build-model-catalogs.ts --version <x.y.z>
```

- `--version` declares **the moh release that will contain the catalog** (ADR-0029
  amendment). Generation is local and human-invoked; a release ships the last
  valid committed catalog and never regenerates.
- `--check` rebuilds and compares **without writing**, exiting non-zero on
  drift. It runs in CI (`.github/workflows/model-catalogs-check.yml`) on PRs
  touching the catalog and weekly, and in the release pipeline at every tag
  (`.github/workflows/release.yml`), so staleness is visible between releases
  and at the exact commit being shipped. A failing release check is the
  recorded trigger to revisit the ownership decision (ADR-0046); it never
  gates a release.
- `--migrate-overrides` is the one-off migration that wrote the sidecars from
  the committed catalogs; it is kept for reproducibility, not for routine use.
- `--models-dev <file>` / `--open-router <file>` read a local snapshot instead
  of fetching (offline runs and tests). The manifest always records the
  canonical source URL, never the local path.

## What comes from where

| field | source |
| --- | --- |
| `cost` (USD per 1M), `contextWindow`, `maxTokens`, `reasoning`, `input` | the aggregators, where they cover the row |
| `planCost` (subscription-plan price entry) | the `source.plan` namespaces a sidecar declares |
| `name`, `api`, `provider`, `baseUrl`, `thinkingLevelMap`, `compat`, `headers` | the sidecar — moh-declared, never aggregator-supplied |
| row identity (which models exist at all) | the sidecar: a row that is not declared there does not exist |

Precedence is **models.dev first** (the namespaces the sidecar names, in
order), then OpenRouter (exact id, the declared vendor prefixes, then the
namespaced-id join — a unique candidate only; several candidates are reported
as ambiguous, never guessed). An override always wins over an aggregator.

Units are converted once, in the builder: models.dev `cost` is USD per 1M as
numbers, OpenRouter `pricing` is USD per token as **strings** (×1e6,
string→number, rounded to six decimals) — a naive copy is wrong by six orders
of magnitude. Upstream input modalities are projected onto moh's vocabulary
(`text`, `image`): `pdf`/`video`/`audio` describe content moh cannot send, and
copying them would claim a capability the client does not have.

## The hand-maintained region

`<provider>.overrides.json` is the only authored surface of a catalog:

```jsonc
{
  "schemaVersion": 1,
  "provider": "zai",
  "source": { "modelsDev": ["zai"], "openRouter": ["z-ai"],
              "plan": { "modelsDev": ["zai-coding-plan"] } },
  "file": { "api": "openai-completions", "provider": "zai", "baseUrl": "https://api.z.ai/api/coding/paas/v4" },
  "rows": {
    "glm-5.2-highspeed": {
      "author": "moh migration (#959)",
      "date": "2026-09-24",
      "reason": "no aggregator record: the row is fully hand-maintained",
      "name": "GLM-5.2 Highspeed",
      "cost": { "input": 0, "output": 0, "cacheRead": 0, "cacheWrite": 0 },
      "contextWindow": 1000000, "maxTokens": 131072
    }
  }
}
```

Every row carries `author`, `date` and `reason` — who declared it, when, and
why. `file` holds the defaults the whole file repeats (a row overrides them by
declaring its own value).

## Guards (all of them fail generation)

- id presence and uniqueness within a catalog;
- a committed row that the sidecar does not declare;
- a `contextWindow` that shrinks against the committed catalog, unless the row
  declares the value or `acceptContextShrink` (the aggregator's correction is
  accepted, not frozen);
- a `contextWindow` the committed catalog had that the build no longer
  produces: no smaller number exists to accept, so the row must declare the
  window itself — `acceptContextShrink` does not cover it (ADR-0046
  amendment, #1004);
- a metered price or a set of tiered rates that the build would drop.

A source outage is "did not regenerate" — the last valid catalog stands.
Generation never produces less than what is committed.

## The artifacts

- `<provider>.json` — the catalog itself, byte-stable for the same input.
- `manifest.json` — `schemaVersion`, `version` (the moh release), `generatedAt`,
  the sources with their fetch dates, per-file sha256 + verdict counts, and
  per-row provenance (verdict, source, namespace, supplied fields, plan entry,
  applied overrides). `PRICING_SNAPSHOT` reads its `version`/`generatedAt`
  from here.
- `generation-report.json` — the human-readable audit trail of one generation:
  coverage per file and against the committed catalog, absent ids,
  cross-source context differences, context-window corrections, price changes,
  and every guard issue.

## Attribution

The data originates from [models.dev](https://models.dev) (primary) and
[OpenRouter](https://openrouter.ai) (hole-filling), fetched at generation
time; moh declares the sources, the precedence and the hand-maintained
region. No runtime dependency on either: the catalog ships with the package
and is versioned in the repo (issue #156, ADR-0046).

## Pricing

The same catalog records approximate USD per-million-token rates used by
`moh usage` and the TUI quota modal. They are estimates, not billing data.
A row may carry two entries — the metered API rate (`cost`) and the
subscription-plan record (`planCost`); the endpoint's declared
`billingPlan` selects which one is used, and a zero-only entry is
"included in the plan", which reads as tokens-only, never as free
(ADR-0029, ADR-0046). Live model discovery never changes prices; models
without a catalog rate remain tokens-only.
