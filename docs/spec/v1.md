# moh — v1 Specification

Consolidation of every decision from the wayfinder map (issue #1, tickets #2–#20). This is the single v1 spec, ready to be sliced into implementation tickets (`/to-tickets`). Each section cites the ticket that holds the full decision record.

## 0. Identity and runtime

**moh** is a provider-agnostic, headless-first CLI coding agent: a library core with thin TUI/CLI clients, with the Matt Pocock workflow integrated natively as an optional mode. Artifacts and public docs in English; conversation replies follow the user's language (#18).

- Language/runtime: **TypeScript on Bun**; npm package (scoped, `moh` npm name is taken) + compiled binaries on GitHub Releases; `--bytecode` breaks Ink, skip it; binary floor ~56–58 MB (#2, #4).

## 1. Architecture (ADR-0002 context) — #7

- **Headless core** (`@moh/core`): the agent loop, event log, registries, permissions. TUI (`@moh/tui`) and CLI (`@moh/cli`) are thin in-process clients; `@moh/extension` is the types-only extension contract package. Monorepo, one-way dependencies, nothing imports the TUI.
- **Event model**: one append-only event log per session — `session_start` (carries `schemaVersion` and `promptVersion`), `user_message`, `assistant_delta`, `tool_call`/`tool_result` (paired by `callId`), `permission_*`, `subagent.spawn/result`, `compaction` marker, `error`, `done`, `cancelled` — exposed as an `AsyncIterable`. The session *is* the event sequence: resume, replay, persistence and the TUI are projections of it.
- **Loop**: same-turn tool calls execute in parallel (`Promise.allSettled`); `AbortSignal` propagated end-to-end; per-turn iteration cap (default ~50, `max_iterations` ends the turn, not the session); tool failures injected into the conversation for self-correction; transport/provider failures retry with backoff.
- **Steering**: user input during an active stream = interrupt + re-send, recorded in the log (P0).
- **Public core surface**: `createSession(config)`, `send(text)`, `events`, `abort()`, `setPermission(...)`, `history()`, `pending()`. Nothing else in v1.
- **Headless mode**: `moh run` uses `--allow`/`--deny` flags + moh.json defaults, never interactive prompts; unpermitted tools fail fast.

## 2. Providers and routing — #8 (ADR-0002), #5

- **Provider-neutral types in core** (`Provider`, `ChatRequest`, `StreamEvent`, `ToolSpec`, `ProviderError`); single method `stream(req, signal): AsyncIterable<StreamEvent>` (`text_delta | tool_calls | usage | finish`). Vercel AI SDK v5 is an invisible implementation detail of the default adapter bundle.
- **Endpoints and Routes**: Provider = implementation; Endpoint = configured instance with own credentials; Route = `endpoint/model-id` with declared fallback chain (user-declared; no model equivalence assumed). Fallback triggers on rate-limit exhausted (after retries) and quota exhausted; mid-stream failure restarts the single-shot request on the fallback.
- **Custom providers**: config-only `openai-comcompat` profile in moh.json (covers Ollama, LM Studio, DeepSeek, Kimi, GLM, Qwen, Grok, OpenRouter) + programmatic `registerProvider`.
- **Error taxonomy**: 9 kinds — `auth`, `rate_limited`, `quota_exhausted`, `overloaded`, `network`, `invalid_request`, `context_length`, `content_filtered`, `aborted` (signal). 429 bodies read to separate rate_limited from quota_exhausted; ambiguous → rate_limited.
- **Capabilities** declared per endpoint (`caching`, `parallelToolCalls`, `multimodal`) drive feature downgrades.
- **Credentials**: env vars default (`MOH_ENDPOINT_<NAME>_API_KEY`), inline keys allowed in moh.json (gitignored). Guided onboarding (`moh provider add` or first-run) with mandatory connection test.

## 3. Tools and permissions — #9

- **Built-in tools**: `bash`, `read`, `write`, `edit`, `glob`, `grep`, `fetch`, `todo`. Contract: `name`, `description`, Zod `inputSchema`, `execute(args, ctx)` with AbortSignal, cwd, progressive output.
- **3-tier permissions**, most-specific-wins: built-in defaults < moh.json < in-session runtime rules. Defaults: read/glob/grep/todo allow; write/edit/bash/fetch ask. Session modes: `normal | auto-accept | bypass` (bypass requires explicit startup flag, marked in the log).
- **Per-argument rules**: bash matched on shell-word tokens with `;`/`&&`/`|` as boundaries; path rules realpath-anchored to project root; one grammar shared by moh.json, TUI, CLI. Out-of-root writes: per-occurrence approval, never persisted.
- **Consent**: blocking TUI modal (yes / always-writes-runtime-rule / no); headless = structured denial the model sees. Runtime-rule promotion to moh.json is explicit only. Consent is auditable (`permission_requested/granted/denied` events).
- **Extension hooks can only veto**, never grant: extension-veto > user rules > defaults. Subagents inherit permission sets at most more restrictively. MCP tools default deny; extension tools default ask.

## 4. Skills and extensions — #10, #19

- **Skills**: pi-compatible `skills/<name>/SKILL.md` (frontmatter `name`+`description`, relative refs); declarative progressive disclosure — name:description index in the system prompt, full file read via tool. No auto-triggering in v1. Locations: `~/.moh/skills` + `.moh/skills` (project wins).
- **Extensions**: default-export `defineExtension({ name, version, apiVersion, setup(ctx) })` from `@moh/extension`; everything via injected `ctx`; npm deps installed by moh with per-change authorization; hot-reload via watchdog with `ctx.state` preserved.
- **Hooks v1** (additive-only): `onSessionStart`, `onSessionEnd`, `beforeModelCall`, `onToolCall`, `onEvent`, `afterTurn`.
- **Versioning (#19)**: independent API spec version, additive-only within a major; `apiVersion` mandatory in defineExtension; major mismatch = load refused with warning (session continues); deprecated APIs survive one full major; `ctx.apiVersion` read-only; mismatch at reload keeps the previous instance.
- **Sandboxing**: none in v1 (consent + veto-only is the trust model).

## 5. Matt Pocock workflow integration — #6, #11

- **Hybrid**: first-party skills are ordinary files bundled with moh, copied to `~/.moh/skills/` (updated from the Workflow upstream only when unmodified, hash check, `minMohVersion` respected, never overwritten without diff + consent). Workflow commands are thin aliases over the generic command registry.
- **Workflow mode**: per-user on/off in `~/.moh/config` (`/workflow on|off`), offered at first run after provider onboarding. When on: first-party skills + workflow commands + wayfinder frontier panel. When off: base behavior unchanged.
- **`moh init`**: scaffolds `docs/agents/{issue-tracker,triage-labels,domain}.md` + AGENTS.md section; non-destructive pi migration. Instructions file: AGENTS.md with CLAUDE.md fallback; tracker abstraction (gh/gitlab/local-markdown) is a core registry exposed as a built-in tool, no workflow privilege.

## 6. Sessions, memory, compaction — #12

- **Sessions (P0)**: append-only JSONL at `~/.moh/projects/<slug>/<id>.jsonl`; bare `moh` resumes latest; `moh resume --fork` forks. Sessions are user data, never in `.moh/`.
- **Memory (P1)**: per-project cross-session at `~/.moh/projects/<slug>/memory/` (index + append-only topic files); automatic post-turn every N=5 turns, non-blocking, fail-silent; extraction/consolidation by the maintenance subagent; injected as a system-prompt section, ~2k token budget; `memory.enabled: false` disables.
- **Compaction (P2)**: in-log `compaction` marker (summary + pointers), log integral forever; threshold ~200k tokens per-endpoint. v1 needs only the event format.

## 7. Subagents — #13

- In-process child `AgentSession`s with their own logs; `SubagentSpec { name, description, systemPrompt, allowedTools, model?, provider?, context }`; presets in moh.json `agents` + built-in `research`/`implement`; only explicit context shared; own per-turn loop caps; depth 1; parallel spawns with concurrency cap (default 3); MCP denied; parent may share or split Routes; usage tokens recorded on spawn/result; the maintenance subagent is a privileged non-spawnable built-in.

## 8. TUI — #14 (decision record: `docs/tui-style-guide.md`)

- Ink 6; vertical stack + modal overlays; multiline input (Enter sends, shift+enter/ctrl+j newline, ctrl+e $EDITOR); ~30fps coalesced streaming + virtual scrollback + `<Static>` settled turns; full streaming-safe markdown; filter-first home; blocking permission modal; contextual tool-call viewer; esc×1 steer / esc×2 stop.
- **Two souls**: vibe mode (plain language, no metrics) and dev mode (same log, dense status line) — a view, not a different app. 9 themes (semantic tokens); labelled full-width boxes; compact mode <60 cols. Onboarding: env-var auto-detect + confirm, wizard fallback. Settings panel incl. in-panel provider management; subagent attribution by title tag + border color.

## 9. MCP — #15

- stdio + HTTP streamable transports; project (moh.json, consent required) and user (`~/.moh/config`, trusted) servers, managed via `moh mcp add/remove/list`; tools named `mcp__<server>__<tool>` in the standard tool contract (collisions = startup error); first invocation of each tool asks, "always" persists to moh.json; lazy start / shutdown at session end; crash → tools `unavailable`, manual restart, no auto-restart; tools only (no resources/prompts); sampling/roots/elicitation refused cleanly.

## 10. System prompt — #18

- **PromptComposer** in the core: typed TS sections `(ctx) => string` in fixed order (base, environment, tools, skills, memory, session-state), reassembled every call; no template language. Base prompt in-package, English; AGENTS.md + CONTEXT.md injected in full with budget cap; CLAUDE.md silent fallback. Skills as name—description list only. User override: full base-prompt file override (`~/.moh/prompts/system.md` < `.moh/prompts/`, project wins); extensions append to a trailing `extension_notes` section. Memory in system; compaction summary in messages. `promptVersion` hash in `session_start`.

## 11. Testing — #16

- **MockProvider (P0)** first-party (`provider: "mock"`), usable without API keys; inline handlers for unit tests + versioned JSON cassettes for e2e/evals; covers loop, permissions, and fallback chains via injected typed errors. **Echo provider (P1)** for context-engineering e2e. **Eval harness (P2)**: deterministic event-trace assertions, `evals/v1/`, run inside `bun test`. TUI smoke via `ink-testing-library`. CI on GitHub Actions; targeted event matchers, not snapshots.

## 12. Docs — #20

- `docs/principles.md` (7 principles, consult before any change), root `CONTRIBUTING.md` deferring to AGENTS.md, `docs/extending/` (index, extensions, library-usage, skills, plus runnable examples), ADRs for hard-to-reverse decisions, CONTEXT.md glossary-only. All public docs English.

## Acceptance criteria (v1)

1. `bun test` green out-of-the-box: core loop, permissions (most-specific-wins, per-argument matchers), fallback chains, prompt assembly, event-log resume/replay — all via MockProvider cassettes/handlers, no API keys needed (#16).
2. `moh run --allow bash` completes a scripted session headless against the mock/echo provider; every event lands in the JSONL log with `schemaVersion` and `promptVersion` (#7, #18).
3. Bare `moh` opens the TUI in vibe mode, resumes the project's latest session, streams markdown, steers (esc×1) and stops (esc×2), and renders a permission modal that writes a runtime rule restorable on replay (#9, #14).
4. A custom provider works via moh.json `openai-compat` profile (mocked e2e); a fallback chain triggers deterministically on injected `quota_exhausted` (#8).
5. A pi-compatible skill in `.moh/skills/` appears in the prompt index and is loaded via read-tool; an extension with matching `apiVersion` registers a hook and can veto a tool call; major-mismatch extensions are refused with a warning and the session continues (#10, #19).
6. An MCP stdio server declared in moh.json registers `mcp__<server>__<tool>`, asks consent on first use, and denies subagent access (#15, #13).
7. `moh init` scaffolds `docs/agents/*` + AGENTS.md non-destructively; `/workflow on` enables first-party skills and the frontier panel without changing base behavior (#11).
8. `docs/principles.md`, `CONTRIBUTING.md`, `docs/extending/` exist and AGENTS.md references them (#20).
